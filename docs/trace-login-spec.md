# Trace 登录注册功能 · 产品说明

状态：已澄清，可进入开发。产品经理：product；目标开发：developer。

## 背景与定位

Trace 是本地优先、数据不上云的时间追踪应用（React 网页）。本功能为它增加「本地身份」：用于区分本机使用者并保护追踪数据，不建立任何云端账号。登录注册的本质是给本机数据上锁，而不是接入账号体系。

## 目标

- 首次使用可「注册」一个本地身份（设置主密码），随后可用主密码登录。
- 未登录时跳转到登录页，无法访问主数据页。
- 凭证与追踪数据均加密落盘，密钥由主密码派生，仅在解锁后存在于内存。
- 登录态可跨刷新保持，闲置约 15 分钟自动锁定。

## 范围

包含：
- 注册页（首次设置主密码，生成并展示恢复码）。
- 登录页（输入主密码解锁）。
- 锁定界面（闲置超时后的重新解锁）。
- 忘记密码 / 恢复入口（凭恢复码重置密码并保留数据）。
- 路由守卫：未登录跳转登录页。
- 本地加密存储层（凭证 + 追踪数据）。

不包含：
- 云端账号、第三方 OAuth、多用户、多设备同步。
- 邮件 / 短信验证码、防暴力破解（本地单用户，暴力破解防护以主密码强度与派生耗时为准）。
- 对既有时间采集能力的改动。

## 关键决策（已确认）

1. 目标产品：Trace（React 网页）。
2. 账号体系：本地身份，只区分本机使用者，无云端账号。
3. 保护范围：主数据页，未登录跳转登录页。
4. 存储：仅前端本地（localStorage / IndexedDB）。
5. 安全级别：生产级单用户，凭证加密、会话校验。
6. 忘记密码：注册时生成恢复码，凭码重置密码并保留数据。
7. 加密范围：凭证与追踪数据都落盘加密；密钥由主密码派生，仅解锁后存在于内存。
8. 会话策略：刷新页面间保持登录，闲置约 15 分钟自动锁定。

## 验收标准

- [ ] 首次打开进入注册页，设置主密码后生成恢复码并强制展示一次；用户确认保存后进入主数据页。
- [ ] 后续打开进入登录页，输入正确主密码解锁并进入主数据页；错误主密码不进入且不泄露细节。
- [ ] 未登录访问任何主数据页路由，一律跳转登录页。
- [ ] 刷新页面后登录态保持，无需重新输入。
- [ ] 闲置约 15 分钟后自动锁定，回到锁定界面，需重新输入主密码。
- [ ] 忘记密码时，凭注册时保存的恢复码可重置主密码，且原有追踪数据不丢失。
- [ ] 落盘数据均为密文：凭证（含恢复码）与追踪数据均不可明文读取；主密码不以明文存储（仅存储哈希 / 派生物）。
- [ ] 解锁密钥只在内存中，刷新或锁定后不残留于 localStorage / IndexedDB 明文。
- [ ] 注册、登录、恢复流程均有明确反馈（成功 / 失败原因），文案符合 Trace「诚实、克制」的品牌语气。
- [ ] 首次注册与登录流程在无网络环境下可用（本地优先，不依赖任何服务）。

## 开发注意（供 developer）

- 主密码派生与数据加解密建议使用 Web Crypto（PBKDF2 + AES-GCM）等浏览器原生能力，恢复码为可读的一次性口令，与派生密钥分离存储（恢复码只用于重置，不直接解锁数据）。
- 密码重置需支持「用恢复码重新派生 / 包装数据密钥」的路径，确保数据不丢——这是本功能里最容易出错、需要自测覆盖的一环。
- 闲置 15 分钟以用户交互为基准计时，锁定后应同时清空内存中的解锁密钥。
- 恢复码展示后不再次回显，防止被截图 / 遗忘两难：提供「重新生成恢复码」需权衡数据可恢复性，若实现请标注风险。

## 未决事项（不阻塞本轮，默认按下述处理）

- 恢复码重置后是否轮换恢复码：默认不轮换，保持简单。
- 主密码强度要求：默认最低 8 位，含字母与数字。

# Trace 用户管理 · Spec

## Problem Statement

Trace 用户在完成首次注册后，无法在应用内自助管理自己的本地身份：不能修改主密码、不能在恢复码泄露或遗失前主动重置恢复码、也不能删除本机身份。这些操作目前只能靠手动清除浏览器数据，既不方便也不安全。

## Solution

在设置页提供「用户管理」自服务入口，让本机唯一身份的拥有者可以：修改主密码（数据不丢）、重置 / 重导恢复码（数据不丢）、删除本地身份（清空身份与全部追踪数据）。删除不可逆，需输入主密码确认，删除后回到注册页，可重新注册新身份。

## User Stories

1. 作为已登录用户，我希望在设置页看到「用户管理」入口，以便集中管理自己的本地身份。
2. 作为已登录用户，我希望能修改主密码，以便在怀疑密码泄露时更换凭证。
3. 作为已登录用户，我希望修改主密码后原有追踪数据完整可读，以便换密码不丢数据。
4. 作为已登录用户，我希望修改主密码时恢复码保持不变，以便不影响既有恢复流程。
5. 作为已登录用户，我希望能主动重置恢复码，以便在恢复码可能泄露时作废旧码。
6. 作为已登录用户，我希望能重新导出 / 查看当前恢复码，以便妥善保管。
7. 作为已登录用户，我希望重置 / 重导恢复码需要当前主密码确认，以便防止已解锁状态下被他人盗用。
8. 作为已登录用户，我希望能删除本机身份，以便彻底移除设备上的账号与数据。
9. 作为已登录用户，我希望删除身份前系统明确告知「不可恢复」，以便我知情后决定。
10. 作为已登录用户，我希望删除身份需输入当前主密码确认，以便防止误删或他人盗删。
11. 作为用户，我希望删除身份后清除全部追踪数据与凭证，以便不留下任何残留。
12. 作为用户，我希望删除身份后回到注册页，以便重新注册一个新的本地身份。
13. 作为用户，我希望所有操作在未登录状态下不可达，以便身份管理受到路由守卫保护。
14. 作为用户，我希望全程离线可用，以符合本地优先的定位。
15. 作为用户，我希望操作反馈文案符合 Trace「诚实、克制」的语气。

## Implementation Decisions

- 目标产品：Trace（React 网页），本机唯一身份；无多身份、无云端、无管理员后台。
- 入口：设置页「用户管理」，仅登录态可见，自服务。
- 改主密码：用当前主密码解锁，更换为新主密码，重新派生 / 包装数据密钥，追踪数据保留；恢复码不变。
- 重置 / 重导恢复码：需当前主密码确认；生成新的恢复码用于后续密码恢复，数据保留。
- 删除本地身份：需当前主密码确认；清空身份凭证与全部追踪数据，不可恢复；回到注册页，允许重新注册。
- 删除的确认门槛用主密码，不用恢复码。
- 唯一身份：数据不涉及多身份隔离，但删除后不留残留加密数据。
- 所有敏感操作复用登录 / 会话 / 路由守卫机制，不新建第二套会话系统。

## Testing Decisions

- 测试只覆盖外部可观察行为：改主密码后用旧密码失败、新密码成功且数据完好；重置恢复码后旧码失效、新码可恢复密码；删除身份后需主密码确认、数据清空、回到注册页、可重新注册。
- 单一测试缝（seam）：身份与数据密钥的生命周期状态机（已注册 / 解锁 / 已删除）。通过用户可见行为驱动，不对内部实现细节断言。
- 与 docs/trace-login-spec.md 的「密码 / 恢复码 / 删除数据」验收口径对齐；Trace 前端为绿地，需按登录 spec 的口径新建测试。

## Out of Scope

- 多身份 / profile 切换、云端多用户、管理员后台。
- 多设备同步、远程管理。
- 恢复码的定期自动轮换。
- 页面风格改版与登录注册动画（独立话题）。
- 退出登录（见 trace-logout 话题）。

## Further Notes

- 本 spec 依赖 docs/trace-login-spec.md 的注册、会话、锁定、路由守卫、加密存储机制先落地。
- 改主密码与重置恢复码都涉及「重新包装数据密钥而数据不丢」，是易错环节，验收需覆盖数据完好。

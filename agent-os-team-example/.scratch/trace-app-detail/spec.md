# Trace 查看详情页面（App 详情）· Spec

## Problem Statement

用户在首页只能看到各 App 的汇总列表，无法深入了解某个 App 花了多久、如何分布。需要一个 App 详情页，从首页点 App 行进入，查看该 App 的统计与时间轴。

## Solution

新增一个独立路由的 App 详情页：从首页点击 App 行进入，默认展示今天该 App 的统计（总时长、占比）与按天聚合的时间轴，可切换日期，并附近 7 天趋势。页面只读，数据复用现有本地加密存储，不新增后端与采集。

## User Stories

1. 作为用户，我希望点击首页的 App 行进入该 App 的详情页，以便深入了解某个 App 的使用情况。
2. 作为用户，我希望详情页显示该 App 的总时长与占比，以便了解它在整体中的分量。
3. 作为用户，我希望详情页展示按天聚合的时间轴，以便看清该 App 的使用分布。
4. 作为用户，我希望默认看到今天的详情，以便快速了解当天情况。
5. 作为用户，我希望可以切换日期查看其它天的详情，以便回顾历史。
6. 作为用户，我希望看到近 7 天趋势，以便了解变化。
7. 作为用户，我希望详情页是独立路由、可前进 / 返回 / 直达链接，以便导航顺畅。
8. 作为用户，我希望详情页只读、不能编辑，以便与「自动记录、不手动记账」的定位一致。
9. 作为用户，我希望详情数据来自本地加密存储、无网络时可用，以便符合本地优先。
10. 作为用户，我希望数据仍是密文、解锁后才可读，以便保护隐私。
11. 作为用户，我希望文案与视觉符合 Trace「诚实、克制」的语气。

## Implementation Decisions

- 详情对象：单个 App。
- 页面形态：独立路由页面，从首页 App 行进入，可返回。
- 核心内容：统计 + 时间轴并重。
- 时间轴粒度：按天聚合展开（现有每日数据直接支撑，不新增采集）。
- 时间范围：默认今天，可切换日期；附近 7 天趋势。
- 只读，无编辑 / 备注 / 修正。
- 数据来源：复用现有本地加密存储，不新增后端与采集。
- 依赖首页 App 清单与本地加密数据读取能力。

## Testing Decisions

- 测试只覆盖外部可观察行为：点首页 App 行 → 进入对应 App 详情；显示该 App 统计与时间轴；切换日期生效；展示 7 天趋势；无编辑控件；离线可用。
- 单一测试缝（seam）：详情页路由与本地加密数据读取。通过用户可见行为驱动，不对内部实现细节断言。
- Trace 前端为绿地，无现成同类测试可复用，需按登录 / 首页 spec 的验收口径新建。

## Out of Scope

- 编辑、备注、修正时段。
- 按会话 / 带时间戳的精细时间轴（需新增采集）。
- 新的数据采集或后端。
- 页面风格改版与登录注册动画（独立话题）。
- 用户管理、退出登录（独立话题）。

## Further Notes

- 本 spec 依赖 Trace 首页的每日 App 清单与本地加密数据读取能力先落地。
- 「时间轴按天聚合」意味着现有每日聚合数据即可支撑，不要求带时间戳的会话数据。

# Trace 退出登录 · Spec

## Problem Statement

Trace 用户登录后没有主动退出登录的入口，只能等闲置 15 分钟自动锁定。用户希望在离开设备前能主动退出，立即回到登录页并清除本机已解锁状态，防止他人继续访问已解锁的追踪数据，同时不删除本地身份与数据。

## Solution

在设置页提供「退出登录」入口。用户点击后立即生效（无需二次确认）：清除当前会话、清除记住的登录态、清除内存中的解锁密钥，并跳转回登录页。本地身份与加密数据完整保留，用户可随时用主密码重新登录。

## User Stories

1. 作为已登录用户，我希望能点击设置页的「退出登录」，以便在离开设备前立即结束已解锁状态。
2. 作为已登录用户，我希望退出后跳转到登录页，以便主数据页重新受到路由守卫保护。
3. 作为已登录用户，我希望退出能清除当前会话，以便本次登录不再生效。
4. 作为已登录用户，我希望退出能清除内存中的解锁密钥，以便数据在未重新输入主密码时不可读。
5. 作为已登录用户，我希望退出能清除记住的登录态，以便刷新页面后仍停留在登录页并需要重新输入主密码。
6. 作为用户，我希望退出无需二次确认即可生效，以便快速离开。
7. 作为用户，我希望退出后本地身份与追踪数据完整保留，以便重新登录后无需重新注册即可看到原数据。
8. 作为用户，我希望退出入口只在登录状态下可见，登录页与锁定页不显示它。
9. 作为用户，我希望退出行为与 15 分钟闲置自动锁定保持一致（同一条锁定语义），以便状态一致、无第二套会话逻辑。
10. 作为用户，我希望退出流程完全离线可用，以符合本地优先的定位。
11. 作为用户，我希望退出后的反馈文案符合 Trace「诚实、克制」的语气。

## Implementation Decisions

- 「退出登录」复用既有锁定机制：等于「手动触发锁定」+「清除记住的登录态」+「清除内存解锁密钥」，不新建第二套会话系统。
- 清除范围：当前会话、记住的登录态、内存解锁密钥，三者都清。
- 退出后路由跳转到登录页，复用既有路由守卫；未登录状态下的主数据页访问仍被拦截。
- 入口位置：设置页，仅登录态可见。
- 无二次确认弹窗（已确认的产品决策）。
- 本地身份、恢复码与加密数据在退出后保留，不得清除。
- 文案遵循诚实、克制的品牌语气，例如「已退出登录」。
- 本功能不包含注销账号（删除本地身份与清除数据）；如未来需要，注销必须输入主密码确认。

## Testing Decisions

- 测试只覆盖外部可观察行为：登录态 → 点击退出 → 落在登录页；退出后刷新仍停留在登录页并需要主密码；重新登录后原数据完好；退出入口在未登录时不可见。
- 单一测试缝（seam）：登录态转换（已登录 ↔ 锁定 / 已退出）。通过用户可见行为驱动，不对内部实现细节断言。
- 与 docs/trace-login-spec.md 中「会话策略 / 锁定 / 路由守卫」的验收标准对齐；Trace 前端尚未实现，无现成同类测试可复用，需按登录 spec 的验收口径新建。

## Out of Scope

- 注销账号（删除本地身份并清除全部数据）。
- 多账号切换。
- 远程登出、多设备同步。
- 对时间采集能力的改动。
- 页面风格改版与登录注册动画（独立话题）。

## Further Notes

- 本 spec 是 docs/trace-login-spec.md 的后续切片，依赖登录注册功能的会话 / 锁定 / 路由守卫机制先落地。
- Trace 前端当前为绿地，实现时应以 docs/trace-login-spec.md 为基线，不重复定义加密与会话机制。
